Access Token 方案会把"Google 签名担保身份"降级成"客户端自己上报的数据"，安全性下降，所以推荐采用 Authorization Code 方案。

The Access Token approach downgrades “an identity Google vouches for” to “data the client self-reports” — a real drop in security — so Authorization Code is the recommended approach.

前端保持登录的完整流程Complete flow: keeping the user signed in

前端启动时先看本地有没有后端签发的会话令牌：有就直接用它登录，没有（或被拒绝）才弹出 Google 授权。

On startup the front end first checks for a session token issued by the backend: if there is one it logs in with it directly; only when there is none (or it is rejected) does it open the Google authorization popup.
